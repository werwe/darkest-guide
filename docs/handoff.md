# 인수인계

2026-11-13 기준. 클라우드 세션에서 만들던 작업을 로컬 개발 환경으로 넘기기 위한 문서입니다.
새 세션은 이 문서와 `README.md`, `docs/overlay-design.md`만 보고 이어서 작업할 수 있어야 합니다.

## 무엇인가

다키스트 던전 1 한글 공략 사이트와, 게임 화면을 캡처해 필요한 정보만 얹어 보여주는 "오버레이"입니다.

- 배포: https://werwe.github.io/darkest-guide/ (GitHub Pages, `main` 브랜치에 병합하면 1~2분 뒤 반영)
- 빌드 없음. 정적 파일만 있고 `js/app.js` 하나에 화면과 인식 코드가 모두 들어 있습니다.

## 쓰는 사람의 환경

- 에픽게임즈 판, **유저 한글 패치** 사용. 공식 번역과 용어가 달라서 `js/data/ko_patch.js`에 이름 대응표(538개)를 따로 둡니다.
- 게임 해상도 2560×1440, 한글 UI.
- **모드 적용**: 장신구 칸이 3개, 물자 상점이 한 줄 9칸입니다. 기본 게임과 화면 배치가 다릅니다.
- 보조 모니터가 **세로**(브라우저 약 770×1230)이고 여기에 오버레이 페이지를 띄웁니다.
- 대답과 화면 문구는 모두 한국어.

## 실행

```
python -m http.server 8765
```

`http://localhost:8765` 를 엽니다. 크롬 확장(`extension/`)은 `localhost`와 `*.github.io/darkest-guide`를 모두 허용합니다.

- 확장 설치: `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램 로드" → `extension` 폴더
- 단축키: 전역 Ctrl+Shift+1. 페이지에 `{ddCapture:1}` 메시지를 보내 캡처를 시작합니다.
- 오버레이(`#/hud`)는 메뉴에 없고 확장 단축키로만 들어갑니다.
- 화면 공유는 새로고침하면 끊깁니다(브라우저 제약).

## 오버레이가 동작하는 방식

1. 단축키 → 화면 공유에서 한 장 캡처 → 캡처를 먼저 보여 주고 분석 결과를 뒤따라 얹습니다.
2. 제목 영역 여러 개를 한 장으로 모아 한 번에 읽어 화면 종류를 정합니다(지도 / 영웅 / 물자). 못 정하면 전체 화면을 읽습니다(느림).
3. 원정 단계: **지도 → 영웅 → 물자 → 탐험**. 단계별 캡처와 영웅별 캡처를 IndexedDB(`dd-overlay`)에 저장해 다시 열 때 바로 보여 줍니다. "탐험 완료"로 비웁니다.
4. 캡처 위 상자는 화면 비율로 정한 영역(`DEFAULT_ZONES`, localStorage `dd.zones7`)에 그립니다. 영역 편집 모드에서 직접 고칠 수 있습니다.
5. 아래 영역에 집사 말풍선과 단계별 안내(영웅 단계는 지금 일행 / 추천 일행 / 후보)를 둡니다.

자세한 설계 원칙은 `docs/overlay-design.md`.

### 인식에서 알아 둘 것

- **지도의 던전 판정**: 고른 원정 뒤에 깔리는 붉은 얼룩 위치(`findSplatter`)를 던전 이름표 아래 표식 줄과 짝짓습니다. 고른 원은 게임에서 커졌다 작아지므로 크기는 쓰지 않습니다. 보스 이름이 읽히면 그쪽이 우선합니다.
- **고른 전투 기술**: 기술 칸 위의 금색 마름모 표식 밝기로 판정합니다(`readSkillRow`).
- **일행 자리**: 캡처한 순서가 곧 자리입니다(왼쪽이 4열). 초상화로 영웅을 알아내는 시도는 실패해서 쓰지 않습니다.
- **기벽**: 붉은 글씨(부정 기벽)는 색 채널 최댓값으로 바꿔 읽습니다.
- 언어는 한·영 인식기를 따로 두고 마지막에 성공한 쪽(`dd.lang`)을 먼저 씁니다.
- 속도: 2560×1440에서 지도·영웅·물자는 2~3초. 탐험은 전체 화면을 읽어서 10초 이상.

### 시험 방법

Playwright로 `#/hud`를 열고 `window.ddOcr.run(img, w, h, false)`에 캡처 이미지를 넣은 뒤 화면과 `localStorage`를 확인합니다. 시야 크기는 770×1230.
시험에 쓰던 실제 캡처는 저장소에 없습니다. 오버레이의 "내보내기"로 받은 묶음을 로컬 폴더에 두고 쓰면 됩니다.

## 지켜 온 결정

- **게임 그림은 커밋하지 않습니다.** 저장소와 사이트가 공개이기 때문입니다. 집사 그림, 대기 화면, 영웅 작은 그림은 쓰는 사람이 자기 브라우저에 지정합니다("캡처에서 따오기", "대기 화면으로 지정"). 번역 파일에서는 이름 대응표만 뽑았습니다.
- **이동과 고치기를 나눕니다.** 위쪽 영웅 이름은 저장된 캡처로 이동만 하고, 잘못 읽힌 영웅은 따로 있는 선택 상자로만 고칩니다. 섞었을 때 목록이 깨졌습니다.
- **추천은 추천일 뿐.** 지금 낀 장신구와 비교하지 않습니다. 상자에는 그림과 이름만 두고 자세한 것은 마우스를 올렸을 때 보여 줍니다.
- **집사 말투**: 공손하지만 은근히 비웃는 간사한 집사.
- 배경 캡처는 테두리 없이 원래 크기 그대로 둡니다. 확대하거나 흔들면 상자가 어긋납니다.

## 알려진 문제

- 탐험 단계는 실제 캡처로 시험한 적이 없고 느립니다. 캡처를 받으면 영역을 정해 빠른 경로로 옮겨야 합니다.
- 나병 환자의 기벽 "강타자"를 못 읽습니다. 두 글자짜리 붉은 기벽도 가끔 놓칩니다.
- 야영 기술 칸 순서는 "공통 3 + 직업 4"로 가정했습니다. 고행자는 4개뿐이라 빠져 있습니다.
- 번역 파일에 DLC 이름(고행자, 방패파괴자, 안뜰, 농장)이 없습니다.
- 공략 본문의 일부 문장은 예전 번역 이름을 그대로 씁니다.
- 지도 판정 수정(삼림지대가 사육장으로 읽히던 문제)은 그려 넣은 얼룩으로만 시험했습니다. 실제 캡처로 확인이 필요합니다.

## 다음에 할 일

### 1. 사이드 패널 (계획만 있음)

상자에 못 담는 추가 정보를 필요할 때만 불러내는 서랍입니다.

- 상자 클릭 → 그 항목의 상세(장신구 수치, 기물 선택지별 확률, 기벽 평가)
- 단축키나 집사 클릭 → 현재 단계 전체 요약
- 위에 검색창. 내용은 기존 공략 화면의 카드를 그대로 씁니다.
- 세로 모니터 페이지에서는 오른쪽에서 나오는 서랍(폭의 85%쯤), 바깥을 누르면 닫힘.

| 단계 | 패널 내용 |
|---|---|
| 지도 | 던전 특성, 추천·비추천 영웅, 보스 요약 |
| 영웅 | 빌드 전체와 대안, 영웅 팁, 기벽 전체 평가 |
| 물자 | 품목별 권장 수량과 이유 |
| 탐험 | 기물 상호작용 표, 적 저항과 주의 기술 |

### 2. 게임 위에 직접 띄우는 오버레이 (검토 중)

- 방향: **Tauri**. 투명·항상 위·클릭 통과 창, 전역 단축키, 화면 캡처만 Rust로 하고 화면과 인식은 지금 코드를 그대로 씁니다. egui는 전부 다시 써야 해서 제외했습니다.
- 조건: 게임이 전용 전체 화면이면 안 됩니다. 게임 설정에 테두리 없는 창 모드가 없어서 **아직 확인되지 않았습니다.**
  - 확인법: 전체 화면에서 볼륨 키를 눌러 윈도우 볼륨 표시가 게임 위에 뜨는지 봅니다. 뜨면 가능합니다.
  - 안 되면 창 모드 + Borderless Gaming 같은 도구로 테두리를 없애는 방법이 있습니다.
- 게임 위에는 상자와 짧은 말풍선만, 긴 내용은 세로 모니터 페이지에 그대로 둡니다.
- 필요한 것: Node.js, Rust, Visual Studio C++ 빌드 도구.

### 3. 탐험 단계

실제 캡처를 받아 기물 이름 영역을 정하고, 지도·영웅·물자처럼 한 번에 읽는 빠른 경로로 옮깁니다.

## 작업 방식

- `main`에 바로 올리지 않고 브랜치에서 작업한 뒤, 쓰는 사람이 "병합"이라고 하면 PR을 만들어 병합해 왔습니다.
- 화면을 바꾸면 Playwright로 770×1230에서 찍어 보고 올렸습니다.
